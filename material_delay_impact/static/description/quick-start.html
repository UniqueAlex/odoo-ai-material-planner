Quick start · Three roles, one shared plan

  1. Planner: open a confirmed purchase order with a partially/unreceived storable material, then Material impact. Set a later assumed arrival. First read shortage at the need time, not just the balance after all receipts.
  2. Compare allocation options. A lower total material wait can make one order worse. Inspect harmed orders, explicit urgency, remaining final shortages and each source's available time.
  3. Assign separate procurement, warehouse and planning/production targets. Give each an owner and a useful deadline.
  4. Procurement: open My plan reviews, verify the specific quantity against the required deadline, and record whether the arrangement can be met. Completing the task can legitimately record a refusal.
  5. Warehouse: open the assigned shared plan, confirm the stock is physically available/unpicked and whether reservation changes are permitted. Do not count a future receipt as current stock.
  6. Planner: review peer feedback. An adopted decision is only a recorded decision; perform approved business changes through normal Odoo operations. If facts changed, recalculate and obtain current confirmations.
  7. Use Copy handoff summary for a short handoff and Copy full record for the detailed history. Export necessary history before uninstall.

Not a full production scheduler: material availability is not manufacturing completion. Lots, expiry, quality release, transportation and operation capacity are outside the validated scope. Candidate search is bounded; no global optimum or financial-cost optimum is promised.

First-time AI setup

  1. Local calculations work immediately, without a key. An Odoo system administrator configures AI for each company.
  2. Use the visible Set up AI card, select the provider and suggested model, then paste that provider’s API key and save. Chat memberships do not include API credit.
  3. Enable the page’s data consent. Test connection, then Verify analysis capability. The latter makes at most two small requests with synthetic data to check tools and structured output.
  4. Saved, connection passed and analysis capability verified are separate states. Saving any change resets verification. Other manually entered models are unverified. Verification does not guarantee every future AI opinion is correct.
  5. For errors, follow the displayed next step: check API credit, key/model permissions, or the Odoo server’s outbound network and supported region.

OpenAI, Gemini and Claude have simulated integration coverage, not completed live acceptance. The customer should run the above checks in their own deployment. Gemini uses Google AI Studio keys; Claude uses Anthropic Console keys. Azure, Vertex AI and Bedrock are not included.
