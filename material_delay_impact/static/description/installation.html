Installation and maintenance

AI Material Planner 19.0.1.1.0 · technical name: material_delay_impact · LGPL-3.

Supported scope

Validated configurations: native Windows 11, Odoo 19, Python 3.12.3, workers=0; and Ubuntu 24.04 with official Odoo 19 Docker, PostgreSQL 16, two HTTP workers sharing one database and persistent data directory. Odoo.sh has not been validated. Odoo Online cannot install this Python add-on. Other Odoo major versions and customer customizations require separate validation. The module depends on standard purchase_stock, mrp and web; no Enterprise-specific integration is claimed.

Install in an existing Odoo 19 environment

  1. Back up the database and complete Odoo data directory. Test first in an isolated copy.
  2. Place the material_delay_impact folder directly in a configured custom add-ons directory. Do not rename the folder. Odoo must be able to read it.
  3. Install Python dependencies in the interpreter or image actually used by the Odoo service. The module includes requirements.txt. It requires requests and cryptography; Windows additionally requires pywin32. Preserve compatible Odoo/OpenSSL dependencies.
  4. Restart Odoo, enable developer mode, update the Apps list, remove the default Apps filter if necessary, search AI Material Planner, and install.
  5. Open a confirmed purchase order containing an unreceived storable material and use Material impact. Review the local calculation before enabling optional AI.

For Docker, bake dependencies into a reproducible image and mount the add-on plus the persistent Odoo data directory. Do not rely on packages installed interactively in a disposable container.

Roles and optional AI

Use normal Odoo purchase, stock and manufacturing permissions according to each person's work. Assign review tasks to the intended planner, procurement or warehouse user and verify access with that user's account. Configuration changes require the appropriate administrator permissions; no credentials should be placed in ordinary business notes.

An administrator can configure a customer-owned DeepSeek, OpenAI, Gemini or Claude API key. Provider usage is billed separately. Local calculations do not need a key. Enable the page's data-sharing permission before calling the provider. See data and fees for transmitted fields.

Upgrade

Keep a paired backup of database, complete data directory and old module source. Replace the add-on with this version, restart Odoo and use the module Upgrade action (or the administrator's normal module-update workflow). Copying files without updating the module is not enough. Verify the registered module version, a local scenario and shared review records before allowing normal use.

Encrypted configuration and recovery

Include data_dir/mdic-private-ai in protected backups; a database-only dump is insufficient. On Windows, DPAPI is tied to the Odoo runtime account and machine. After account or machine migration, configure the key again. On Linux, encrypted settings and protected decryption material must be restored together with the correct ownership and permissions. Settings are scoped to database name and company; renamed copies may need reconfiguration. Treat these backups as secrets.

Removal and rollback

Export review records and take backups before uninstalling. Uninstalling removes module-owned records; it is not a substitute for rolling back a database. For rollback, restore matching database, source and data-directory backups. Remove saved AI configuration through settings before uninstalling if it should be removed; revoke the provider key separately when needed.

First-time AI setup

  1. Local calculations work immediately, without a key. An Odoo system administrator configures AI for each company.
  2. Use the visible Set up AI card, select the provider and suggested model, then paste that provider’s API key and save. Chat memberships do not include API credit.
  3. Enable the page’s data consent. Test connection, then Verify analysis capability. The latter makes at most two small requests with synthetic data to check tools and structured output.
  4. Saved, connection passed and analysis capability verified are separate states. Saving any change resets verification. Other manually entered models are unverified. Verification does not guarantee every future AI opinion is correct.
  5. For errors, follow the displayed next step: check API credit, key/model permissions, or the Odoo server’s outbound network and supported region.

OpenAI, Gemini and Claude have simulated integration coverage, not completed live acceptance. The customer should run the above checks in their own deployment. Gemini uses Google AI Studio keys; Claude uses Anthropic Console keys. Azure, Vertex AI and Bedrock are not included.
